Catalogul frontend: trei probleme reproduse pe scriptul original

Au fost executate zece scenarii în Chromium: cinci controale pozitive și cinci contraexemple, grupate în trei mecanisme de defect. Lectura traseului backend și limita dovezii

Au fost verificate separat patru surse din traseul catalogului: alegerea sursei DB/JSON, parametrii servletului, paginarea Java și implementarea Python de referință. Lectura a identificat o ipoteză pentru pagini foarte mari: înmulțirea offsetului într-un int Java poate produce un index negativ. Ipoteza nu a fost executată și nu este numărată ca defect runtime confirmat. Ea privește sursa JSON; nu se transferă automat sursei DB și nu explică prin ea însăși erorile simulate în proba frontend.

Proba următoare trebuie să invoce implementarea originală pe un catalog sintetic, cu pagini normale și extreme, după un protocol aprobat. Adaptarea propusă rămâne în paginarea existentă, fără un motor nou de catalog sau stoc.
