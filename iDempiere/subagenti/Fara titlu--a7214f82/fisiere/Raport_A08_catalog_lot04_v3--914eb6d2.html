A08.R12.CATALOG.1 — Catalogul nu mai execută cereri după o eroare de rețea sau JSON invalid

Severitate propusă P2; cazuri N01, N02.

Declanșator: Prima cerere fetch este respinsă ori response.json aruncă excepție; utilizatorul încearcă apoi o altă categorie.

Observație: Scriptul înregistrează excepția JavaScript, dar nu resetează loading. Clickul ulterior schimbă titlul și categoria activă, fără o nouă cerere; cardul inițial rămâne.

Explicație din cod: state.loading=true este setat înainte de await, fără catch/finally; false este atribuit doar la sfârșitul căii reușite.

Limita probei: Original JS pe DOM sintetic; eroarea rețelei/API este injectată, nu atribuită unui defect backend. Persistență numai în starea JS a paginii.

Adaptare propusă: Păstrează funcția existentă, adaugă tratarea explicită a erorii și eliberarea stării în finally, cu păstrarea ultimei liste validate și un mesaj/reîncercare vizibile. Dacă se folosește identificator de cerere pentru concurență, finally trebuie să elibereze doar cererea activă potrivită.

Reverificare după corecție: N01 și N02 permit o cerere ulterioară reușită fără reîncărcarea paginii; eroarea are stare vizibilă distinctă de rezultat gol.

A08.R12.CATALOG.2 — Răspunsul HTTP 500 cu JSON este afișat ca rezultat valid fără produse

Severitate propusă P2; cazuri N03.

Declanșator: GET catalog întoarce HTTP 500 cu obiect JSON {error:synthetic}.

Observație: Scriptul consumă JSON fără a verifica response.ok, afișează Rezultate:0 și mesajul normal de categorie goală, ascunde încărcarea următoare. Schimbarea ulterioară a categoriei reușește, deci acesta nu este blocajul N01/N02.

Explicație din cod: Lipsește verificarea statusului HTTP; items,total,has_more lipsă sunt convertite în lista goală/zero/false.

Limita probei: Un răspuns de eroare sintetic arată comportamentul original al frontendului; nu dovedește că backendul real emite acea formă exactă.

Adaptare propusă: Validează response.ok și structura răspunsului înainte de a înlocui lista; afișează eroarea ca eroare în componenta existentă. Refolosește același contract de catalog, fără un motor de catalog paralel.

Reverificare după corecție: N03 nu afișează o eroare HTTP drept absență comercială de produse; S03 continuă să afișeze corect o căutare goală validă.

A08.R12.CATALOG.3 — Schimbarea filtrului în timpul unei cereri pierde ultima intenție și afișează cardurile vechi sub titlul nou

Severitate propusă P2; cazuri N04, N05.

Declanșator: Cererea pentru categoria/căutarea A rămâne pending, apoi utilizatorul alege B.

Observație: UI actualizează titlul/filtrul B înainte de fetchProducts; acesta returnează imediat când loading este true. Răspunsul A este aplicat după aceea sub titlul B, iar cererea B nu este trimisă. S05 arată că o selecție C după încheiere funcționează.

Explicație din cod: Garda loading suprimă resetul nou fără coadă sau anulare, iar răspunsul vechi nu este corelat cu filtrul afișat.

Limita probei: Concurență controlată determinist între evenimente DOM și frontiera fetch; nu este test de rezervare stoc sau consistență DB.

Adaptare propusă: Păstrează componenta existentă și leagă fiecare răspuns de o fotografie imuabilă a filtrului. Pentru noua intenție folosește anularea cererii precedente/identificator de generație sau o singură cerere pending pentru ultimul filtru; actualizează titlul și lista în mod coerent.

Reverificare după corecție: N04/N05 fie blochează explicit schimbarea, fie cer B și afișează B; răspunsul A nu poate ajunge etichetat B. S04 rămâne fără dublarea paginii și S05 permite reluarea normală.

Limite și resurse

  • Nu UI ZK sau site real
  • Nu recepție API Java/Python, contabilitate, disponibilitate G3, drepturi/comisionari sau flux comandă
  • Nu recepție întreg fișier deși scriptul integral este încărcat
  • Probe de rețea sunt simulări determinate la frontiera fetch; erorile/efectele JS sunt originale
  • Stilurile și templatele complete nu sunt randate; screenshot probează starea funcțională DOM, nu design/responsivitate reală
  • Valoarea inputului pregătită în fixture, apoi Enter real/submit original; debounce input 280ms nu este probat.
  • Nu probăm toate filtrele, sortarea, resetarea, input-debounce, responsive, accesibilitate completă, coș, checkout, conturi, retururi, taxe sau traduceri.
  • Datele și etichetele sunt sintetice, compatibile cu selectorii citiți; templatele complete nu au fost randate.
  • CazulS05 repetă precondiția de concurență și probează reluarea; nu constituie o a patra constatare.
