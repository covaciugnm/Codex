# Audit round 1 — inventory, first version and restore parser

Status: intermediate; no final 10/10 awarded while extraction/decompilation/delivery remain in progress.

## Scope corrected

The original and recent manifests initially expose 13 references for 12 unique vendor APK/XAPK containers. Independent inspection of all four existing GitHub Releases found two additional derived APKs on the build branch: full-rebuilt and romania40. The correct scope is 14 unique containers, distinguishing vendor builds from locally modified derivatives. Full Release metadata and published digests are preserved in `release-inputs.json`.

The original complete/applications/extra library manifests were checked and contain no additional APK filenames beyond the known baseline AINOTE, Loomy Android and default Translate. Two logical source paths for default Translate share one SHA-256 and must not cause duplicate delivery.

## Findings and corrections

1. Initial restore parser did not reject missing TAR padding/footer, trailing partial header or invalid header checksum. Root corrected the parser, added a fixture target root and robust file writes. Independent fixtures now pass all 12 cases, including valid zero-length and chunk-spanning entries, duplicate/unlisted entries, path traversal, body corruption, checksum failure and truncated gzip/TAR forms. Tests touched only `.work/audit-fixture`, not the real CAS. Evidence: `test-restore.cjs`, `restore-fixture-results.json`.
2. Initial extractor review requested explicit comparison of recent APK input hash/size against the collection manifest rather than merely computing a new hash. Executor reports correction. Final all-input verification remains pending.
3. Resource-only splits must be accounted for rather than silently skipped as decompiler jobs. First-version output records each split, its manifest identity and all resources/native libraries byte-for-byte. This is acceptable for static unpacking; it is not described as source recovery.
4. Existing build-branch editable-source/AOT ZIPs must be indexed for content deduplication, not only the older repository manifest. Architect supplied the index; executor will apply a final remapping pass before packing.

## First-version independent check

Bavvo 1.0.1222 was independently checked against its actual XAPK bytes: container SHA-256 and size, four component APK SHA-256 values, 1,515 logical extracted file hashes/sizes and component entry counts all matched. All CAS-referenced file bytes were reread and matched their hashes. Evidence: `first-version-results.json`.

This check does not yet validate the decompilation stage or resolve every existing-baseline pointer. Those are required later, along with complete 14-container coverage, source availability findings, version indexes, final packs and materialization verification.

## Baseline limitations retained

The existing Translate 1.0.3899 reconstruction README explicitly records JADX 1.5.6 exit code 3, 301 errors, and complete Smali fallback export for 47,219 classes with zero export failures. Decompiled Java is not original Java/Dart/C++ source and the Gradle export is not a verified rebuild. These limitations must remain visible in the new per-version references.
