# Nu. Este 200 Gb/s **total** per nod, nu 200 + 200

Aici documentul precedent era greșit și l-am corectat.

## Cum e cablat de fapt ConnectX-7 în GB10

Fiecare nod are **două porturi QSFP** care negociază link 200G — de unde și confuzia. Dar în spate:

- ConnectX-7 e alimentat de SoC prin **două legături PCIe Gen5 x4**, fiecare ≈ 100 Gb/s
- Fiecare port QSFP conține **două MAC-uri de 100 Gb/s**, aliniate pe cele două legături PCIe
- Sistemul de operare vede **patru interfețe de rețea**, nu două

**Bugetul total al nodului este ~200 Gb/s, partajat între cele două porturi.** Folosirea ambelor porturi **nu dublează** debitul — e necesară tocmai ca să ajungi la 200. Dacă împerechezi greșit interfețele, nodul folosește o singură legătură PCIe și rămâi la 80–100 Gb/s.

ServeTheHome formulează direct: sunt **două legături de 100G însumând 200 Gb/s, nu 2 × 200G**.

| Scenariu | Debit real |

# GPUDirect RDMA on DGX Spark: Not Supported

Based on the forum discussion, **GPUDirect RDMA cannot be enabled on DGX Spark**, regardless of configuration efforts.

## Why It's Not Supported

The fundamental limitation stems from the DGX Spark's architecture. As an NVIDIA engineer explained: *"the system memory returned by the pinned device memory allocators cannot be coherently accessed by I/O peripherals like PCI Express devices. Hence the GPUDirect RDMA technology is not supported."*

The GB10 lacks dedicated GPU memory (no HBM). Instead, it uses only LPDDR5 memory attached to the CPU, making GPUDirect RDMA impossible to implement.

## Performance Without GPUDirect RDMA

Users report achieving approximately **22 GB/s (~176 Gbps) with dual 200G connections**, though one benchmark showed **25.67 GB/s** (~208 Gbps) at roughly 52% efficiency. This performance is actually reasonable given the unified memory architecture.

## Workaround Strategy

Since GPU and CPU share the same virtual address space, developers should:
- Allocate buffers using `cudaHostAlloc` or standard `malloc`
- Register them with RDMA without requiring GPUDirect
- Pass pointers directly to CUDA kernels without `cudaMemcpy` overhead

This approach bypasses the need for GPUDirect RDMA entirely while achieving competitive performance.
