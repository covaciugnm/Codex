# Roadmap reutilizabil pentru fiecare roman

Etapele sunt porți de acceptare, nu simple bifări. Duratele sunt eforturi orientative înainte de măsurarea productivității; remedierile se adaugă. Nu se însumează mecanic activitățile paralele. Pragul >9,50 și auditul dublu se aplică fiecărui livrabil, inclusiv fiecărui capitol și fiecărei traduceri de capitol.

## G00 — Mandat și sistem editorial

| Element | Cerință |
|---|---|
| Intrare obligatorie | Niciun roman nou declarat final |
| Obiectiv | Mandat trasabil, roluri, porți de calitate, modele și mecanism verificabil |
| Activități | Înregistrează instrucțiunile; definește independența; testează blocările; cercetare preliminară de selecție |
| Livrabile | Manual, fișe de post, rubrici, modele, registru, validator și teste |
| Producător / responsabil | P-MANAGER + P-SYSTEMS |
| Auditori separați | A-GOVERNANCE + A-SYSTEMS |
| Rezultat măsurabil | 100% cerințe trasate; testele trec; nicio aprobare fictivă |
| Ieșire | Configurație acceptată; cartea poate intra în G01 |
| Efort orientativ | 1–3 zile; fără garanție |

## Dependențe și control al progresului

G00 → G01 → G02 → G03 → G04 → G05 → G06 → G07/C01…C26 + loturi → G08 → G09 → G10 → G11. După G11, RO urmează G12→G14 și DE urmează G13→G15 în paralel. Ambele ramuri sunt obligatorii pentru G16. G17 cere aprobarea explicită a transferului.

Fiecare rezultat compus poate avea mai multe fișiere într-un manifest, dar ambii auditori verifică întregul pachet. Sublivrabilele cu responsabili, criterii sau dependențe distincte primesc ID-uri și audituri proprii. Un raport de capitol nu acoperă automat lotul.

Procentul de roman se calculează din proza EN acceptată raportată la ținta65.000 și se plafonează la100%; pragul minim50.000 și stadiul editorial sunt afișate separat. Draftul nu este carte finalizată. După primele două capitole auditate se estimează calendarul folosind orele reale de scriere, editare, audit și remediere. Niciun termen nu justifică trecerea unei porți respinse.

Toate depunerile, auditările și remedierile se arhivează conform PROTOCOL_ARHIVARE.md, inclusiv rundele respinse și rezultatele verificărilor automate.
